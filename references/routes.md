## Subscription and privacy

[OpenCode Go](https://opencode.ai/docs/go/) documents the opencode-go provider, included model quotas and optional Use balance spillover. Existing Go login on disk is used; the runner requests `opencode-go` via a generated config (`enabled_providers: [opencode-go]`, `share: disabled`) but managed settings can take precedence. Preflight and worker runs share filtered environments (OpenCode config/permission overrides, Cursor key/endpoint, and common `*_TOKEN`/`*_SECRET`/`*_API_KEY` credentials removed; `HOME`/`PATH`/`XDG` preserved), which is not comprehensive scrubbing. This runner does not change credentials or enable balance spillover. Muse Contributor is marked training-enabled and not zero data retention. Avoid excluded/private material; use another authorized route for it.

[Cursor Grok 4.6](https://prod.cursor.com/docs/models/grok-4-6) places Grok in the Cursor Models pool. The standard route has lower listed token prices than Fast; more reasoning is not free quota. [Cursor usage limits](https://prod.cursor.com/help/models-and-usage/usage-limits) explain on-demand billing after included usage if enabled. Dashboard spending settings were not inspected or changed during setup. No CLI-only promise of zero overage is made. Disable provider-side overage if a hard subscription-only ceiling is required; do not silently change account settings. Grok Build and Antigravity are likewise subscription/account-backed native routes: existing logins are used, the runner never enables overage or changes billing, and no zero-overage guarantee is made.

## Why bounded delegation

The default routing is an engineering choice, not a model leaderboard conclusion. Muse implements; Grok reviews independently; deterministic tests decide behavior. Research is only added for unresolved questions. Measure accepted changes, retries, material review findings and elapsed time on real work before changing defaults.

[Anthropic's multi-agent engineering report](https://www.anthropic.com/engineering/multi-agent-research-system) reports substantial token overhead and notes that coding often has fewer independent tasks than research. This supports avoiding an always-on large swarm, but does not establish performance or savings for these models. Keep contracts and summaries small; offload expensive exploration and implementation; do not repeat their whole work in Codex.

## CLI contracts

- [OpenCode configuration](https://opencode.ai/docs/config/): OPENCODE_CONFIG_CONTENT is a runtime override; managed settings can take precedence.
- [OpenCode permissions](https://opencode.ai/docs/permissions/): deny-by-default with narrow read/edit grants. Tool permissions and receipts are not OS isolation.
- [OpenCode models](https://opencode.ai/docs/models/): model variants are provider-specific.
- [Cursor CLI](https://cursor.com/docs/cli/overview): ask mode is read-only.
- [Cursor headless mode](https://cursor.com/docs/cli/headless): unattended edits generally require force; this workflow uses Grok only for read-only work and does not add force.

## Route limits (current transport)

- Muse: training-enabled; no shell or nested delegation; default 60 model steps (`--steps 5..120` bounded override, not a quality guarantee).
- Cursor Grok (legacy): ask-only read-only review; trust-scoped (`--trust` only for an already authorized/trusted workspace); live retrieval/search not assumed — the coordinator supplies sources.
- Grok Build: `plan` for ask, `acceptEdits` for work; `--no-subagents` and `--disable-web-search` are fixed; never bypass/force flags; tool-heavy exploration carries latency/timeout risk.
- Antigravity: `plan` for ask, `accept-edits` for work; fixed `high` effort (never `xhigh`); strict rejected output on empty `response` or any `denied_actions`; never `--dangerously-skip-permissions` and never `--disable-slash-commands`; work quality still unmeasured.
- Provider quota, cost, and quality remain live or unknown at invocation time; refresh inventories when invoked and stop a route on quota/auth/billing errors.

## Limits and escalation

Stop a failed route on quota, authentication or region errors; do not rotate accounts or evade limits. Use fresh sessions by default to avoid cross-task contamination. A workflow may use many workers over a large task, but concurrency and total calls stay bounded. The runner serializes each workspace and times out process groups; the coordinator enforces the overall call budget and acceptance. No automatic fallback, force/yolo/bypass flags, overage changes, global state files, or benchmark harness are part of this package.
